T3 Code: design audit

The look is quiet and well made. The things people do hundreds of times a day are where it slips: the command palette can run the wrong command, thread switches wait, and the composer drops a frame per key.

Summary

Intent (assumed): a tool developers keep open all day to run and review agent threads. Compact, instant, quiet. Its users notice a dropped frame, a lying spinner and a stale label. Direction note: direction.md.

Verdict: the visual system is close to right for this intent. The fixes that matter most are not visual. Make the palette trustworthy, make switching threads feel instant, and stop the add-project flow from quietly creating the wrong folder.

Top 3 changes

  1. Make the command palette trustworthy and instant. Today, after you type, the row that Enter will run has no highlight. A title match like "Link pull" loses to "Copy thread ID". It also takes 114–212 ms to paint and then fades and scales for 200 ms.
  2. Make thread switching feel instant. A switch takes 800 ms cold and 280–430 ms warm on desktop, and 0.9–2.1 s on a 4× slower CPU. Start loading on hover or press, and render the rows as real links.
  3. Fix the "Local folder" path. The input starts with ~/. Paste an absolute path after it and you get ~//tmp/…, a new empty folder under your home. The agent then works in the wrong place.

Outside Critly

  • The palette has no Rename, Archive, Delete, Mark unread or Fork for the current thread. All of them exist in the thread context menu (hooks/useThreadActionMenu.ts).
  • Thread titles stay as the first 40 characters of the prompt ("Read src/monitors.js and src/s…"). "Regenerate title" exists, but it is manual and buried.
  • Diff counts flip their order. The panel header says "+27 −2" and each file says "−1 +2".
  • The inline "3 changed files +9 −0" card is scoped to the latest turn. The panel opens on "Changes +27 −2" for the whole worktree. The numbers disagree and neither one says which scope it uses.
  • After a turn finishes, a sidebar row shows nothing new. "Mark unread" exists in the menu, but finished and unseen threads don't get a mark of their own.
  • The pairing page doesn't say where a token comes from: "run npx t3 pair on the host" or "Settings → Connections".
  • The blue sidebar art appears only on Dev and Nightly builds (SidebarStageBackdrop.tsx:15-23). It is a channel marker, but it is also the heaviest shape on those builds (2.7–8.7×). Nightly users see it every day, so a smaller pill would carry the same information.

Performance

Production build (vite build, served with vite preview) against the local server, 3 runs each, medians. Desktop: 1280×800, no throttling. Phone: 390×844, 4× CPU, 1.6 Mbps / 150 ms. The container's CPU is slower than a recent laptop, so compare ratios, not absolutes. The textarea baseline below was measured on the same machine.

5.4–7.1 sopen a thread, desktop (phone: 22.8–25.2 s)
283–434 msswitch thread, warm (cold 799 ms; 4× CPU 0.9–2.1 s)
114–212 msCtrl+K to painted palette, then a 200 ms fade
32 msmedian keydown in composer (plain textarea: 16 ms)
2.07 MBcompressed JS to open one thread (6.2 MB decoded)
10–28%frames over 33 ms while scrolling a long thread

While waiting, you see the T3 splash on load (first contentful paint at 120 ms) and the old thread during a switch. Nothing tells you a switch is in progress. DOM size is fine: 1,383 elements on the long thread, which shows the virtualized timeline doing its job.

In order: system, then composition, details and performance. Each batch is about one PR.

Batch 1: System (tokens first)

Diff text colors to -700 in light (6). Give the dark sidebar a role token instead of #000 (8). Collapse the type scale to five UI steps (21). Snap spacing and radii to the scale (22). Raise row metadata to 4.5:1 (7). Files: index.css (lines 128, 178-185, 1222-1231, 2078), chat/DiffStatLabel.tsx, chat/ModelPickerContent.tsx.

Method and limits

  • Setup. I ran the dev server with an isolated home in a scratch directory, with real data: 3 projects and 6 threads. The data came from 19 real Claude Haiku 5.5 turns, which made real edits and commits, plus one 11-turn thread. Codex isn't installed in this box, so I saw its error state but never a working Codex turn.
  • Screens. New thread, chat with a long thread, sidebar, composer and model picker, Settings (General and Providers), command palette, the Link PR dialog, and the diff panel. Each at 1280×800 and 390×844, light and dark. Also the pairing page, the thread context menu and the delete confirmation.
  • Tools. Critly's inventory.js, check.js (__critlyCheck({})) and taste.js (report, squint and overlay) ran in an authenticated Playwright page. I didn't use the CLI, because it can't get past pairing.
  • Not reached. The first-run "no projects" hero (NoProjectsHero.tsx), hosted onboarding, the Electron shell, the native mobile app, the terminal drawer, approvals (every thread ran with Full access), plan mode, and the pull-requests screen with data.
  • Dev only. The blue sidebar art is the Dev/Nightly channel marker. I judged composition on the stable look, and the production build confirms the art isn't there.
  • I changed no app code. This is an audit, not a fix.
